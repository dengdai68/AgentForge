# 长期沟通

新建/编辑沟通的关闭按钮位于底部主操作左侧，打开时不聚焦选人输入框，候选仅在主动进入输入时展开，并复用窗口空间自适应的顶层浮层。新建/编辑弹框仅显式关闭，Escape 不丢选择草稿。会话列表用更大的两字头像；私聊始终使用员工本身的身份颜色，选中不改色；群聊按稳定会话 ID 分配已有身份色。

群聊使用 `kind=group`、独立 `name` 和 `memberAgentIds`；每次创建产生新会话，即使成员相同也不复用团队群。未传 name 时，Store 在创建时按所选员工姓名以中文逗号连接生成完整名称，不截断；显式自定义名称为 1–100 字符。后续改成员或员工姓名不自动改群名。新建对话只选成员，选择一人创建/打开其私聊，选择多人创建群聊；添加团队仅批量加入员工。已有群聊编辑为一人时仍保留原群身份与历史。私聊继续按员工复用，已删除员工的私聊从列表隐藏，原历史不删除。旧团队会话保留原消息/会话 ID；读模型从已记录成员事实读取，显式编辑/删除团队或员工时脱离旧团队标识，保存独立成员，不进行全库迁移或重置。

私聊输出仍为严格 `{reply}`。独立群聊输出为 `{reply, mentionAgentIds}`，普通答复用空数组，确需其他员工回答时填当前可用成员 ID，正文中的 @ 不自动投递。所有成员消息公开保留，指定接收者只决定唤醒；没有转交/接棒概念。每条含明确 mentionAgentIds 的新消息都向对应员工入队，包括已参与或正在执行的员工；同一员工按 FIFO 串行处理，失败的队首等待人工重试或取消。完成回调按 deliveryId 幂等，rootMessageId 仅保留来源，不用于抑制后续消息。普通答复及致谢应使用空数组结束讨论。员工会话仍各自隔离，任务派工/咨询协议不变。

员工删除为 `status=deleted`、`deletedAt` 的持久标记，目录/选人/团队和群聊成员列表不再显示，禁止编辑和新投递；自动移除当前团队与独立群聊的成员引用，取消尚未执行的沟通投递并留审计。已运行沟通可以保存最后答复，但不再唤醒其他员工；正在执行的任务保留全部冻结成员继续完成。任务协作中的旧发言与控制台证据保留；员工 Tab 不列出已删除者。已删除员工不再阻止当前角色/扩展退役，冻结调用仍使用已保存的提示词/文件。

认证 POST /api/communications 创建私聊或群聊，PUT /api/communications/:id 部分修改群名称或完整成员数组。单聊不显示成员栏，顶部只用图标打开该员工控制台。群聊成员栏显示人数和与员工卡片一致的头像，姓名单行省略，固定的控制台图标不被挤压。点击成员在居中只读弹层查看名称、角色/共用提示词、系统提示词和能力简介；姓名后的图标从最右打开该成员的真实日志，不提供其他员工 Tab。群聊顶部没有控制台入口；双击标题区编辑群名，Enter 保存、Escape/离开取消，保存失败保留输入，轮询不覆盖编辑草稿。宽屏并排，窄屏使用可关闭的成员/控制台区域，不丢聊天草稿。

私聊使用 `{ "reply": "回复正文" }`，群聊使用 `{ "reply": "回复正文", "mentionAgentIds": [] }` 的闭合 JSON 协议；schema 要求当前模式的全部字段，不声明或要求 handoffToAgentId。未知输出字段拒绝，不自动将模型正文转成投递。私聊由目标员工答复，群聊按人类本次 @ 投递给指定成员，不 @ 时仍广播给当前可用成员；成员普通答复不自动唤醒其他成员，只有群聊结构化 mentionAgentIds 指定时投递，正文中的 @ 不投递。经理在普通沟通中没有额外路由权限。不提供转交字段或自动转交；已保存消息/投递/调用事实保持原样，不重写历史或重建原生会话。Task/Run 内的经理派工与咨询不变。

未选择会话进入沟通时，列表成功加载后打开 updatedAt 最新的会话；没有会话保持空态，读取失败不猜测。显式会话选择及正在阅读的会话不因轮询排序变化而切换。

员工姓名、简介、职责、能力、角色绑定及插件/MCP 选择变化继续使用同一原生会话 ID；下一次调用更新系统指令和工具配置，不清除记忆。投递快照在发送与显式重试时嵌入员工当时绑定的角色提示词文本，排队中的投递保持发送时快照。实际 Runtime 连接（Provider、可执行文件、模型或原生 profile）或会话启动目录变化才重建，明确记录原因，已保存聊天与消息游标保留。移除扩展后新调用不再启动该服务；旧历史中的工具结果不等于当前仍持有工具。

员工职责、沟通规则及执行环境进入应用系统指令。当前目标只注入一次，不再发送近期聊天数组；原生会话负责历史。新外部消息按成员游标首次投递，成功保存回复后确认，失败不确认；会话重建如实记录，旧 transcript 不自动重放。详细协议见 docs/22。

控制台顶部保留当前员工名称、「最新」「刷新」及关闭按钮，不提供其他成员 Tab；加载更早记录在工具栏外，原有按成员/游标查询与隔离语义不变。

沟通附件以会话为归属，原始文件保存在 `communications/<会话ID>/attachments/<附件ID>/<原文件名>`；SQLite 只保存名称、相对路径、字节数、SHA-256 和消息关联。先通过认证 HTTP 上传（单文件最多 20 MiB），再发送 attachmentIds；允许仅附件消息，引用必须属于当前会话。重名文件不覆盖，下载检查归属、路径与完整性；模型上下文只带本轮可见消息的附件位置，不把二进制内容塞入提示词。员工仍从自己的独立目录启动，提示词给出会话主目录和附件绝对位置。上传不等于已发消息，失败重试保留草稿和已上传引用。

会话列表只依据员工回复的 unreadCount 显示未读提示；人类发送、排队、失败重试均不产生未读点。读确认仍要求窗口可见且已读到消息尾部。

单聊标题栏图标和群聊成员姓名后的图标打开最右侧面板；群聊宽屏显示聊天、成员、控制台三栏，中等窗口打开控制台后隐藏成员列表并提供成员开关，窄屏控制台独占内容区域。控制台内提供当前员工名称和关闭按钮，窄屏也能返回聊天。关闭不清空草稿或阅读状态。按成员分页读取真实沟通调用，保留每次投递/尝试的关联、公开 thinking/text/tools、失败、原生会话及已脱敏提示词快照。复用任务空间控制台 renderer、内容完整性校验与按需读取；不创建虚假的 Task/Run。旧调用没有正文时如实说明，不补造内容。控制台读取和附件下载不会确认聊天已读。

本轮无新增 CLI 命令：现有 CLI 覆盖任务与配置，不覆盖长期沟通；员工/插件/MCP 配置输入、输出、帮助和 schema 不变。沟通附件与控制台通过同一认证 HTTP 提供，不扩大 CLI 权限。

沟通页支持数字员工私聊和独立群聊，历史跨任务保留。消息通过持久化投递执行，每位接收成员有自己的 Provider 会话；不同会话不会合并成一个模型上下文。

人类可发起私聊或新建群聊；在群聊里指定或广播的成员各自直接答复，成员也可明确 @ 其他员工提问。回复本身不广播唤醒全员，不执行 Task 派工或转交。

会话记录支持 Markdown、未读、搜索与历史分页。侧栏只显示未读摘要；运行失败保留在对应记录中。输入草稿、阅读位置与选中会话属于界面状态。

客户端把人类发送的消息靠右、数字员工消息靠左，发送者身份来自持久消息，不按接收者推断；内容、时序、投递、未读确认和历史分页不变。正文保持左对齐，窄窗口内自然换行。

Store 拥有会话、消息和投递事实；`communication.mjs` 调用 Runtime；`communication-store.mjs` 管理状态；客户端 renderer 通过认证 HTTP 操作。

私聊/群聊共用稳定发送者配色：人类蓝色，员工按 ID（无 ID 时按名称）分配青绿或紫色。名字、加粗、引用柔和强调；待回复和读取失败沿用信息/错误色。颜色不是新的投递/执行状态，不改变可见性、未读确认或分页。

Runtime 连接变化或旧会话缺少连接指纹时重建 Provider 会话，已保存消息仍保留。历史查询见 [员工历史](19-agent-history.md)。

Runtime 可用开关为当前实例调用门禁：停用时发送新沟通会拒绝；已排队调用在真正调用 Provider 前再次核对，拒绝时保留原投递/失败证据，恢复后按原重试入口继续。正在运行的调用不终止；员工原生会话和模型/档位快照不被开关改写。详见 docs/15。

普通沟通可使用 DeepSeek Harness SDK；与任务共用同一系统/角色指令通道和所选扩展，仍只答复或明确 @ 群聊成员，不扩大业务操作语义。成员独立原生会话继续通过 Store 确认和恢复，模型或连接改变按原规则重建。

员工可绑定有序 roleIds；沟通发送/显式重试时解析整组 roleSnapshots，并按顺序进入应用系统指令。排队/历史快照不受角色编辑或解绑影响，角色变化本身不重建会话。

沟通失败保留原消息、投递和调用历史，nextAttemptAt 为 null，不由轮询自动重试。失败消息下提供“查看控制台”和“重试”；重试使用当前员工配置，未确认原生会话时创建真实新会话，已确认时续接。同员工 FIFO、其他群成员并行及服务重启恢复在途调用保持原规则。

沟通应用提示词保留沟通与 Task/Run 的入口区分、讨论答疑边界和实际交付指引；移除固定中文、逐项 Git/发布/凭据限制、代表自己/经理无特权以及附件读取/非指令的重复句子。输出协议、真实附件路径与统一来源/如实表达规则保持；不改变 API 权限或存量原生历史。

群聊名称双击使用紧凑单细边框输入。成员执行中显示绿色脉冲点；同一控制台按钮再次点击收起，切换会话或离开页面关闭控制台。running 按该会话全部运行中投递计算，不依赖消息分页。

成员详情与任务中心共用身份、简介及直接展开的 Markdown 提示词；群聊正文保留 @ 标记，不再额外重复渲染“→ 接收人”一行，实际路由不变。

群聊右侧成员头像尺寸保持，行间空白缩至约三分之一；员工间任务澄清不属于长期群聊操作。

沟通附件选择拆为图片与文件；常见位图（PNG/JPEG/GIF/WebP/AVIF/BMP）在草稿及消息中展示缩略图，点击使用原生 dialog 全窗口预览，Esc/关闭返回原焦点。文件点击按原名下载，图片也保留下载入口。损坏图片明确提示且仍可下载。认证 GET `/api/communications/:id/attachments/:attachmentId?preview=1` 复用归属、路径和 SHA-256 校验，通过文件签名确定位图 MIME；不可预览返回 415，未认证返回 401，普通下载不变。SVG/HTML 只作文件下载。预览不新增元数据或模型输入。
