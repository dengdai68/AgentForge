# SQLite

业务元数据由 `server/persistence.mjs` 保存到 SQLite，Store 是领域写入入口。文件快照、提示词和执行正文由 Run Files 保存，不把大块文件内容写入业务状态。

认证使用独立数据库，保存密码摘要、会话摘要与登录限流。Runtime 私有配置独立存储，不进入公开目录读模型。

业务数据库及其历史派生库位于 `<工作目录>/records/`；认证库仍在 `~/.agentforge/<实例>/`。启动定位、停机校验搬运与故障处理见 [配置目录与工作目录](30-storage-layout.md)。测试使用临时目录。发布包不包含数据库、用户配置或凭据。

当前面向单机单管理员。没有分布式队列、多租户数据库或多节点写入协议。

插件/MCP 摘要与 Runtime 主设置保存在配置目录的 configuration.json。Store 使用同一内存状态维护领域规则，保存时剥离全局配置；configuration_revision 只记录已提交的 JSON revision，业务表只存员工/角色关联与冻结事实。阶段 JSON、SQLite 事务及启动恢复保证跨文件一致性。清单搜索分页使用已加载元数据，不扫描安装目录。

## 实体持久化和历史读取

`workspace_snapshots` 仅保存小型业务标量与 installationId；带 ID 的领域集合存 `workspace_entities(collection,id,position,value_json)`，事件沿用独立表，扩展主清单在配置 JSON。实体变更日志提供脏 ID/集合替换标记，增量写入与 `workspace_revision/workspace_changes` 同一事务；无变化事务不落盘。失败不推进持久缓存/水位，并由 Store 回滚内存逆操作。启动按 ID/位置建立稀疏集合，历史正文按需读取，干净强引用每集合最多 256 项；当前目录仍可按需查询完整详情。

集合尚未落入实体/事件表时，脏日志不能代表完整基线：首次保存必须全量物化该集合（包括空集合），再在同一事务移除快照内对应数组。干净日志和仅部分实体改动都不得跳过初始化；失败时保留原快照及未初始化标记，提交后才进入增量模式。这是当前领域数据的存储表示转换，不改写配置协议或冻结事实。

目录、自动化及触发记录在 SQL 内过滤、计数、分页，最后展开当前页对象。事件时间与错误索引用于全局日志 keyset；Run/成员/Trace/状态/会话索引用于控制台、未读与巡检。历史工具索引另存可丢弃派生库，以持久水位补齐变化。显式全快照仍用于隔离测试/内部检查，不进入 App/CLI 常规刷新路径。设计取舍见 [docs/28](28-performance-architecture.md)。

当前存储归属以 [配置目录与工作目录](30-storage-layout.md) 为准：配置、认证、Runtime、插件/MCP 清单及源文件保存在 `~/.agentforge`；员工、角色、团队、工作流、自动化、任务与沟通及执行内容保存在工作目录，默认 `~/.agentforge/workspace`。清除所有数据删除整个当前工作目录，保留配置和登录。插件/MCP 列表与 Runtime 设置使用私有 JSON，SQLite 只存业务关联及配置提交 revision。

## 集合加载边界

`load({lazy:true})` 只装载快照和集合名称，不查询每个集合的全部 ID。首次读取某集合的长度、元素或身份索引时才查询其 ID/position；正文仍由有界缓存按行读取。Journal 的 release 对未访问集合为空操作，未修改集合直接跳过保存；替换未访问集合时仍加载旧 ID，确保删除差集正确。`onLoadDiagnostic` 报告集合名、行数、耗时，不输出正文。认证与 JSON 配置查询不打开业务库；业务首次请求及后台恢复共享一次初始化。
