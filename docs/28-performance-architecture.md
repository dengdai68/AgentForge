# 架构决策：有界读写与执行资源

目标是消除随全部历史增长的交互和执行成本，保持 Store 的同步领域事务、持久提交后通知、冻结历史和成员会话语义。范围对应性能审查 P01–P22；不清除真实实例，不新增数据库服务；唯一新增生产依赖是下述图片处理库。

## 数据与事务

SQLite 继续是唯一持久状态源。集合按实体保存；Store 使用实体变更日志，只有被写入的实体产生快照和持久更新。事务异常恢复原对象及集合位置，成功提交后才发通知。无变化事务不写数据库。短小的 SQLite 原子提交保留同步确认，不能用异步后台保存使已返回成功的命令在崩溃时丢失。

当前状态、历史记录、文件内容分别管理。查询先使用 ID、归属和状态索引筛选/分页，再投影当前页；历史工具索引按已提交变化维护，查询不重建全历史。Bootstrap 只返回启动所需信息。App 与 CLI 共用分页、搜索和过滤语义。

## 资源与文件

执行预算只管理实例资源，不改变经理决定或同员工串行/跨员工并行规则。等待可取消且公平，暂停和终止不能留下预约资源。诊断、SSE、正文缓存和历史视窗有明确的字节预算与生命周期。

文件和扩展缓存区分目录发现、元数据和内容完整性。复用必须有失效条件，不以缓存跳过必要的篡改检测。上传下载采用有界流；缩略图与原图分开，原文件保持不可变、认证和完整性校验。

## 验收

每项修复记录在原审查报告，使用同一小/中/大合成数据比较；另覆盖事务回滚、重启、分页游标、篡改、取消和慢消费者。真实 Provider 执行验收独立于合成压测。性能结果必须注明环境和未覆盖条件。

## 图片派生资源决策

为服务端生成真实缩略图，引入固定版本 `sharp`（Apache-2.0；实际打包的 `@img/sharp-libvips` 发行包声明 LGPL-3.0-or-later，其 README 列明所含库的许可），不依赖操作者安装图像命令，也不增加通用 Electron 文件桥。只处理通过附件归属/字节摘要验证的位图；限制输入像素、两项并发及缓存字节，原始文件不改变。缩略图是可丢弃派生数据，原图在全屏打开时才读取。参照 [sharp 构造器](https://sharp.pixelplumbing.com/api-constructor/)、[resize](https://sharp.pixelplumbing.com/api-resize/) 和 [资源控制](https://sharp.pixelplumbing.com/api-utility/)。原始上传/下载走有界流；读取使用匿名临时快照先验证摘要，再发送，避免先发送未验证字节。

## 查询与内存边界

- `workspace_entities` 保存按 ID 可定位的领域实体；独立事件表和扩展目录表保留。`state-journal.mjs` 只记录受影响属性的逆操作及脏实体，不复制全部状态。持久提交失败回滚事务内对象；变更通知发生在提交后。
- 启动仅载入实体 ID/位置及当前配置。历史正文以稀疏集合按需加载，每集合至多保留 256 个干净强引用；活动对象通过弱引用保持身份，事务修改会固定到提交。归档和软删除保留事实，不自动清除业务历史。
- `workspace_revision/workspace_changes` 与业务提交原子更新；历史派生库提交索引与水位，重启补齐已提交变化。无相关变化不重建索引。首次构建仍须读取现存历史，是一次性成本，不能把热查询数字用于承诺首次重建耗时。
- App 启动读轻量 shell；员工、角色、团队、工作流、任务、会话、自动化和触发记录先 SQL 过滤/分页，再展开当前页。名称选择用轻量关联目录；详情单独读精确 ID。CLI 同步使用这些端点，`--all` 是显式逐页读取。
- 任务 compact 只含成员最新 Trace、计数、当前投递和待答问题；协作默认 30 条、上限 100，按消息位置向前读取。答复/问题、投递、重试和验收关联单独补齐；本轮控制台精确读取 Trace。
- 控制台/聊天历史视窗上限 200 条；阅读旧记录时实时流不改变当前窗口，使用“最新”返回末尾。控制台正文/提示词缓存分别 8/4 MiB，聊天 Markdown 4 MiB；切换任务/离开工作区释放相关缓存。
- 任务与沟通控制台加载更早页时合并相邻记录，超过 200 条才淘汰新端；保持可见行滚动锚点。恢复最新会重新请求最新页，轮询出现覆盖缺口时重新定位，不拼接不连续历史；当前窗口保留对应调用元数据。
- 沟通控制台按会话/员工索引先取事件页，仅补齐当前页调用的开始、结束与提示词；任务/沟通正文按事件 ID 读取。投递、重试、恢复和任务删除状态查询使用 ID/Run/状态索引，不能因展示正文或领取一次执行而加载其他任务历史。

## 执行和 I/O

`execution-budget.mjs` 是编排层共享资源池，任务与沟通使用同一个实例预算；默认总数 8、单 Provider 4，可用 `AGENTFORGE_MAX_EXECUTIONS` / `AGENTFORGE_MAX_PROVIDER_EXECUTIONS` 指定 1–64。按任务/会话轮转，内部 FIFO；排队写出“等待实例执行资源”日志，取消和退出释放等待，结束释放名额。它不替代经理派工，不改变同成员串行规则，也不是任务权限或业务优先级。

10 秒巡检只选活动状态；巡检每批最多 16 个、自动化每批最多 8 个，以 `setImmediate` 让出事件循环，检测本身不等待模型。触发沿用幂等键和 Store 事务。停用自动化删除一次构造 Task/Run 集合，各关联集合各过滤一次；文件清理仍采用暂存、持久状态与启动恢复，202/pending 如实保留。

文件摘要缓存最多 10,000 项，按设备、inode、大小、mode、mtimeNs、ctimeNs 失效；每次仍 lstat，未命中以 4 路、256 KiB 块读取，读取前后核对路径/描述符，禁止符号链接。目录发现缓存元数据，Hook 请求合并且期间新请求会再扫一轮；普通目录排序缓存最多 4 MiB/128 项、1 秒，目录变动立即失效，每页文件仍重新校验。首次发现、Git diff 与变化文件的实际读写成本不能省略。

扩展按安装批次目录时间戳维护 ID→路径索引；单次绑定/执行准备通过 AsyncLocalStorage 共享验证结果，后续操作重新核对元数据。模型目录按 Provider、可执行文件版本、环境摘要、账号/配置文件时间戳缓存 30 秒，并发请求合并；手动刷新绕过已完成缓存，失败不缓存。

诊断使用 Worker 写入。普通排队 4 MiB，关键记录预留至 6 MiB；普通超额计数丢弃，关键失败同步兜底，退出有刷新屏障。只清理本实例自有诊断文件：10 MiB 分卷、256 MiB/30 天，保留当前分卷；领域事件与 Artifact 不受此规则影响。SSE 超过 256 KiB 待发送缓冲或持续背压时断开，客户端重连按持久页恢复，不允许无限积压。

附件原件上限 20 MiB；上传/下载流式处理。下载先校验并复制到匿名私有临时文件，验证完成才返回已固定字节，避免未校验内容提前发送；代价是每次原件下载需要临时磁盘空间。缩略图最多 144 px、输入最多 16 Mpx、两路生成、等待 32 项、16 MiB 缓存；缓存仍须通过原件元数据/摘要校验。HTTP 使用私有 ETag 重验证，全屏保留原图。

BMP 不受 libvips 解码支持，保留原有浏览器原件预览，不伪称生成了缩略图；其他超出解码像素限制的图片显示预览失败，仍可点击查看或下载原件。文件 HEAD 错误显示 HTTP 状态，不尝试解析没有正文的响应。

## 取舍

同步 SQLite 小事务保留“成功即已提交”的语义；不引入第二套异步领域写入顺序。慢磁盘仍会增加单次提交延迟。缓存只减少重复工作，不能跳过域规则、路径认证或文件篡改检查。完整历史导出/内部快照、首次索引、搜索计数和用户要求的整批删除仍与实际数据量相关；它们不再处于每个 Provider 事件或每次轮询的默认路径。

首次物化是增量持久化的前置条件：只有已经成功提交过完整集合的缓存才允许跳过无变更集合或只保存脏 ID。快照数组剥离和集合初始化标记在同一事务提交，失败仍可从原快照重试；无需改变当前配置协议或冻结执行历史。
