# 自动化

自动化是定时生成独立 Task/Run 的配置，不是普通任务。任务中心查询、bootstrap、通知仅包含普通任务；自动化触发记录通过分页接口访问，详情复用现有任务工作区。

## 配置与查询

名称 title、目标 objective、memberAgentIds/teamIds、workflowTemplateId、acceptanceCriteria 与普通任务共用验证，附加 cron（五段、数字及 * , - /）、enabled。工作流可省略、null 或空字符串，使用固定默认协作快照，不自动选目录中的首个模板。时区使用本机当地时间，保存配置时解析并记录 IANA 时区；timeZone 不再接受外部输入。团队在保存时展开成员，执行时冻结最新员工/工作流；历史保存配置版本及执行快照。优先级废弃，所有入口明确拒绝。

GET/POST /api/automations；GET/PUT/DELETE /api/automations/:id；GET /api/automations/:id/triggers；POST /api/automations/:id/trigger；POST /api/automations/preview。列表支持 search、status、page、pageSize，返回 items/total/page/pageSize/totalPages；触发按时间倒序，默认20条。删除仅允许无历史的配置，有历史请停用。

## 调度与完成

10秒检测，只同步领取到期记录并异步执行；同一计划时刻幂等。每个自动化最多一轮活跃执行（含暂停），重叠时记 skipped；离线错过不补跑。手动立即执行不改变计划时间。禁用不终止已运行任务。

实际创建下一轮前，在同一 Store 事务验证配置与 Runtime、创建新 Task/Run，并自动确认所有已无活动执行/待投递的待验收前轮。确认记录 actor=system、时间和下一触发ID，不生成协作消息。不确认错误、暂停、取消或执行中的记录；新配置失效或触发跳过时不确认。调度启动后的模型错误保留新轮失败，前轮确认不回滚。

自动化参与者只有经理和员工；提示词与领域命令拒绝向人类澄清、交接或人类消息。缺失事实先查资料或咨询经理，无法完成应明确失败，不编造。经理交付后仍为 awaiting_acceptance；操作者可提前确认。普通任务的人类角色、澄清、验收和原员工重试不变。

## 交互

左侧自动化入口；列表搜索/状态/分页。新建与编辑复用任务创建弹窗，内容优先，验收标准折叠，成员/工作流选择，Cron 输入缩为约三分之一宽，右侧同一行预览下次执行时间；按钮取消、保存为停用、创建并启用。配置保存失败保留草稿，防重复提交。触发列表返回保留分页；详情保留协作、文件/CHANGE、控制台、任务详情及执行操作，自动化隐藏人类输入和筛选。

## 架构决策

采用固定版本 [cron-parser 5.4.0](https://github.com/harrisiirak/cron-parser) 计算时区、DST 和下一时间，不自行实现日期算法；仅开放五段数字 Cron，拒绝秒、宏、随机值及扩展语法。Store 拥有配置/触发与原子确认；独立 scheduler 不直接修改状态、不等待模型。SQLite 继续存元数据，不引入后台服务。离线策略以超过一分钟的未处理时刻视为错过，记录一次跳过并从当前时间计算下一时刻，避免睡眠恢复时洪泛补跑。

普通任务旧 priority 输入已废弃，调用方须删除字段；不重置实例、不重写历史冻结事实。

界面中的计划时间按本机当地时区显示；元数据保存 UTC 时间点，历史配置仍保留当时的时区与 Cron。

自动化列表的空目录与无匹配结果使用共享 directory-empty 的标题＋说明两行结构，与团队等目录页保持同等高度，不单独设置页面高度。仅展示变化，CLI/API 不变。

自动化列表采用任务中心表格样式；状态选择立即查询并重置页码。触发列表保留计划时间，不重复展示触发时间或筛选提交按钮。详情顶部仅显示 Cron 与下次执行时间，启用/停用分别用主操作色/危险色。配置以紧凑的标签和内容呈现成员、流程、描述及执行规则，空验收标准不展示。生成的任务名称为 `自动化名称#yyyy-MM-dd HH:mm:ss`（24 小时制），定时触发取本轮计划时刻，手动触发取本轮触发时刻，按配置记录的当地时区格式化。触发记录首列展示真实任务标题；HTTP/CLI 触发回执、触发列表及 latestTrigger 提供 taskTitle。跳过或启动失败且未生成任务时 taskTitle 为 null，界面显示「—」；历史任务标题不重写，自动化改名不改变已生成任务标题。

进入单个自动化后，以返回、名称/状态、编辑/启停/立即执行及 Cron/下次执行组成详情页头，替代通用“自动化”标题；离开详情恢复其他页面标题。

员工角色筛选紧随搜索并保持同高；自动化列表输入防抖查询、状态即查，移除搜索/重置按钮，筛选与表格间距为8px。详情收紧页头，以浅色值区分 Cron/下次执行；触发记录移除筛选/刷新，计划时间与触发方式定宽，状态说明同行，窄屏表格内部横向滚动。配置采用无分割线的「标签：内容」，成员仅头像与姓名，流程名称可打开已有详情并显示说明，空验收标准隐藏。HTTP/CLI 查询能力与任务执行规则不变。

自动化触发记录仅按是否存在已创建的 Task/Run 提供「查看详情」，运行、暂停、待验收、完成、失败或取消均保留；未生成任务的跳过/创建回滚记录无入口。操作列固定在表格右侧，窄窗口无需横向滚动寻找详情。

自动化生成的 Run 与普通任务共用成员并行调度：经理可以 assignments 批量派工、wait 等待部分结果，只有所有执行和队列结束后才能提交本轮待验收。错误立即禁止新领取，在途成员收尾；这不改变自动化禁止人类澄清、重叠触发跳过、下一轮按配置确认前轮的规则。

已停用自动化详情显示删除入口，明确确认后终止关联执行并删除全部任务和触发记录。HTTP DELETE /api/automations/:id 与 CLI automations delete ID --yes 等价。启用状态拒绝删除；退出超时不删除记录。新建/编辑的成员选择、流程模板和工作目录说明都属于正文滚动区，底栏只保留提交动作。

## 大量触发与删除

自动化和触发记录采用 SQL 搜索/筛选/分页，先取当前页再关联任务/Run，最新触发使用索引。到期检测只读已启用且到期定义，每批最多处理 8 个并让出事件循环，实际执行进入任务/沟通共享资源池；原有幂等、冲突跳过、下一轮验收规则不变。

删除已停用自动化时一次构造全部 Task/Run ID，各关联集合一次过滤并在同一事务提交；文件暂存/清理的恢复机制保留，清理未完成仍返回 pending，不伪报完成。

自动化配置必填managerAgentId，从所选员工（含团队展开成员）中单选。保存、编辑、每次触发均校验该员工存在、可用且属于成员集合；配置和触发快照保存其ID，生成Task时显式传递，不按员工kind推断。旧配置缺少该字段时须编辑选择，失败触发保留明确原因且不创建任务。正在执行的冻结经理不变。

员工启动目录：新普通任务与自动化采用 `<工作目录>/tasks/<TaskID>/<RunID>`；沟通采用 Store 首次分配并持久保存的 `<工作目录>/communications/<会话ID>`，群聊成员共享文件目录但原生会话独立。既有任务路径不重写，已分配的沟通目录不随工作根切换；目录变更重建模型上下文并保留聊天历史。内部附件、提示词和执行内容仍由 Run Files 管理，详见 docs/30-storage-layout.md 与 docs/17-communication.md。
