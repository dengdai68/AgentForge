# 产品与协作

AgentForge 在本机组织由 Claude Code/Codex 驱动的数字团队。

协作读模型以消息/事件为主线，按 sourceMessageId 或唯一的已有定向消息、Dispatch/Trace 引用关联真实派工；不按正文、名字或时间猜测，不回填历史。deliveries 明示投递当前状态，history 保留每次执行与重试的实际时间，经理协调为全流程范围。CLI 保留完整投递/执行事实、验收关联及有界文件 ID/名称引用（files 最多8项、fileCount 为总数）；完整文件列表用 artifacts 查询。已知员工交接结果信封从 rawResponse 提取已记录的报告正文，去除重复结构化结果，原始消息和控制台事实不变。客户端协作区展示成员总结、沟通和关键人类状态，保留单一“本轮控制台”入口；不自动附加投递状态、技术失败/重试通知、验收文件清单或平台验收说明。长消息全文一次渲染 Markdown，超过10行仅收起区域，展开不重建 DOM，Run 内保留阅读状态。控制台无顶部错误摘要，失败记录在日志内标红；员工状态按自己的最新 Trace 显示错误/执行中/正常，重试成功后清除旧错误。未验证事项保留员工原文，不自动判定交付质量；存储、调度、模型输入和人类确认规则不变。

## 核心对象

任务空间的协作时间线完整展示团队的派工、交接、成员咨询/答复、人类指令与澄清，以及人类恢复、取消和最终确认。消息统一对团队公开，具体接收人只表示交给谁处理；无具体处理对象的发言只显示发送者。派工正文与实际投递关联，可跳转到对应执行控制台；技术失败、重试及完整投递事实在控制台与 CLI 中查询。

- 数字员工：名称、简介、提示词、能力、Runtime、Skill/MCP；仅区分普通员工和项目经理，仓库说明写在提示词；可绑定多个共享提示词角色，也可不绑定。
- 角色：名称与纯文本提示词，代表一组员工可共用的系统提示词；独立导航管理，不是员工类型、职责标签、派工或权限规则。
- 团队：项目经理、业务员工和本机人类。通过搜索选择员工，已选成员单独展示。
- 工作流：节点、人员需求、交付说明和预期交接关系。
- 任务：目标、团队与冻结工作流；一次执行对应一个 Run。

## 执行方式

人类提交目标，经理选择员工并推进交接。员工可以咨询其他成员、向人类提问、报告问题和提交普通文字结论。平台负责消息、派发、运行与记录；业务判断由专业员工完成，经理依据协作情况推进，人类显式确认完成。

每位员工独立会话。同一 Run 的后续调用恢复原生会话；不同员工可以共享同一工作目录。

## 创建任务

弹框以标题和内容描述为主，验收标准可选且默认折叠。底部同排选择团队与流程，附小字工作目录。提交仍创建 Task 并尝试启动 Run，启动失败保留待开始任务；经理依据所选团队和冻结流程派工。

## 任务空间

- 协作记录：交接、咨询、问题与人类回复，正文按 Markdown 展示，先渲染最近 30 条。
- 工作目录：当前文件与 CHANGE 复用紧凑目录树，分别展示最新文件与变化；文件和差异按选择读取，当前文件支持下载完整原始字节，不再展示交付版本。历史 Artifact 仍保留，不删除审计事实。
- 控制台：点击员工才加载历史，每页 50 条；可见工具行收起时也展示 Bash 命令和 Read/Write 文件路径，正文与提示词展开且接近可视区域时读取。成功 Read 展开显示 Done，失败保留错误，Write 展示已记录写入文本而非 JSON 信封；无法解析或未保存时如实说明。
- 任务详情：团队、工作流链接、相对工作目录与任务描述；复制目录得到绝对路径。
- 任务标题左侧提供返回列表按钮，返回保留搜索条件。控制台不重复回显协作消息正文，协作全文仍在协作记录。

## 本机使用

桌面首次启动设置管理员。Runtime 使用已安装并登录的本机 CLI；模型可从目录选择或手工输入，思考等级按 Provider 能力配置。登录态持久保存，默认不因时间自动过期，退出或重置后撤销。

员工以本机用户权限运行，工作目录是启动位置。平台不提供 Agent 沙箱或多租户隔离。客户端与 CLI 的账户与数据边界见认证和客户端文档。

Runtime 增加固定 DeepSeek Harness项，任务和普通沟通均可选择；与 Claude Code/Codex 共用可用开关、模型和思考配置及员工绑定。当前支持 DeepSeek Harness 内置 DeepSeek API Key/账号模型路由，未导入用户自定义 pi-ai 路由。所选 Skill/MCP 与历史按原生接口加载；不兼容的第三方 Hook/Subagent 不标记为支持。
