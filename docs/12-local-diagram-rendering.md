## 背景

开发手册需要展示数据模型、系统架构与任务流转。手写 SVG 的绝对坐标和路径在节点增加、文字变长或画布缩放时容易产生悬空线、穿越节点和难以导航的问题。Console 是原生 ES module 静态页面，没有 React、Vue 或既有前端构建框架。

## 决策

使用 `@antv/x6` 3.1.8 作为关系图画布依赖，并使用 EPL-2.0 的 `elkjs` 0.10.0 作为自动布局依赖。浏览器通过 AgentForge 服务显式提供的 `/vendor/x6.js` 与 `/vendor/elk.js` 读取已安装包的 UMD 构建物；不使用 CDN，不把整个 `node_modules/` 暴露为静态目录，也不引入 React/Vue。

开发手册三图及工作流管理/任务空间的流程拓扑统一使用声明式 `nodes[]` 与 `edges[]`：

- 节点定义尺寸、HTML 内容、端口和语义类型；所有边必须引用真实 source / target port。
- 动态 WorkflowTemplate / Task 工作流使用已有 ELK Layered 整理节点坐标。共享 workflow-layout 优先生成不穿节点的直线或单直角路线；指定端口或返工回路不能这样连接时，使用 X6 Manhattan 正交避障。ELK失败保留当前图，显式整理失败如实提示。
- 开发手册的系统架构与任务流转图是固定语义图：以人工分层、明确端口和显式折点表达实际边界与回路；固定图不依赖自动避障路由，避免连接线在模块或边界附近绕行。端口仅用于准确锚定边，不作为编辑把手展示；边界使用低对比实线，避免被误认为选中态。不能把循环协作图交给通用分层算法随意改写语义。禁止手写悬空 SVG path。
- 架构图与流程图先画只读的边界泳道，再放入实际组件/状态节点；每条边必须写明调用条件、数据归属、状态变化或回路原因，不能只标抽象名词。
- 开发手册使用 X6 内置 `MiniMap`、画布 panning、`zoomToFit`；页面自身的按钮、捕获阶段滚轮监听和键盘 `+` / `-` / `0` 都直接调用图实例，而非 CSS transform。捕获阶段监听保证页面滚动不会吞掉图内缩放。
- 工作流只读图和编辑图都提供放大/缩小、百分比（点击恢复100%）、适应画布、滚轮缩放及空白处拖动平移。工作流手动缩放5%–300%，键盘+/-/0与按钮等价。首次显示适应画布；视口尺寸变化保留用户缩放。只读详情的“整理布局”仅改变本次视图，不写回模板；编辑器“一键整理”在用户保存时通过既有position字段持久化。
- 开发手册和只读工作流不可创建、删除、重连或改变领域数据；工作流编辑器经认证HTTP/Store保存节点与连线。
- 工作流拓扑优先由 `edges` 读取，省略时从节点 `dependsOn/handoffFrom` 归一：ELK 的分层 DAG 计算决定列、行、正交折点与交叉最小化；模板图只使用流程定义，Task 图只读取冻结 `workflowSnapshot`、`nodeStates` 与 `nodeAssignments`。同一组件不能把模板状态当作 Run 状态。
- 图的可读性优先于一次性塞入全部字段：默认视口的固定图必须保持正文可读的缩放比例，先收敛模块与边界，再考虑增加节点；节点、线标签、边界至少保留可辨识空白，不能依赖用户先放大才能读懂图。

## 取舍

React Flow 具备类似能力，但要求 React 运行时，不适合为现有原生 ES module 页面引入框架迁移。Cytoscape.js 更偏关系网络分析；X6 保留端口、只读交互与小地图，ELK 专门解决动态流程的层级、间距和折线路径问题。

X6 会增加本地前端资源体积；当前静态页面壳在进入开发手册、工作流管理或任务空间时按可见范围创建关系图实例，离开相应页面即销毁。它不是领域数据源：图定义仍须依据 Store、Orchestrator、Run Files 的契约维护。

领域图移除独立问题清单节点及连线，执行图以协作反馈表示问题发现、处理与核验结果，不再展示独立问题关闭状态机。静态 SVG 回退同步。


工作流只读视图与极简画布共用节点/连线协议。web/manual-graphs.mjs从edges显示交接摘要，非紧凑详情优先保存位置；无保存位置的纯依赖图继续ELK自动布局，含普通返工交接的图使用有界默认布局。web/workflow-editor.mjs复用本地X6，自己管理Graph/ResizeObserver生命周期，不新增CDN/框架；共享文字投影位于client/workflow-description.mjs。画布图形不执行条件、绑员工或决定任务状态。

流程节点用圆角矩形，条件节点用菱形，边标签优先显示分支条件。编辑器监听外层 surface 的有效尺寸，隐藏预览时不写入0尺寸；返回画布主动恢复尺寸，保留视口/选择/图数据，不重建 Graph。

保存坐标的只读工作流图沿用编辑器140×52/140×76节点尺寸，标题限制在图形内，避免缩小编辑节点后预览图仍按旧尺寸放大而相互覆盖；未保存坐标的自动布局及任务紧凑图维持原有布局方式。节点与端口位于连线上层，避免已有边的命中区域遮住继续绘制分支的连接点。

共享呈现模块 web/workflow-layout.mjs 管理节点尺寸、四边端口的简化正交路径、ELK整理和视口交互；不拥有领域规则、不评估条件、不派工。右/左/上/下均可连入或连出，sourcePort/targetPort保存人工选侧；一键整理可重选连接侧以减少绕线，保留节点ID、源/目标、正文与分支条件。不能承诺任意带回路/固定端口的图都只用一个折角；必要时使用外侧正交折线，避免穿过节点。编辑期间变更定义会使旧整理结果失效，关闭时销毁监听与Graph。原始规则及冻结事实见docs/03。
