# 第一次使用：让 AI 团队把素材整理成发布说明

这篇教程面向已经使用 Claude Code、Codex 或 DeepSeek Harness 的开发者。先用一份自带素材的小任务熟悉员工、协作和文件交付，流程不依赖外部仓库、插件或 MCP。

安装包支持 macOS 13+ / Apple Silicon。应用按 Apache-2.0 开源，模型订阅、API 和工具费用另计。本文以 [v0.1.6-beta.1](https://github.com/dengdai68/AgentForge/releases/tag/v0.1.6-beta.1) 为下载基线；截图来自同版本的隔离实例。

## 1. 安装与准备

1. 从上述 Release 下载 `AgentForge-0.1.6-beta.1-arm64.dmg`，打开后将应用拖入 Applications。若要使用正式版，去[正式版下载页](https://github.com/dengdai68/AgentForge/releases/latest)，按该版本说明操作。
2. 当前安装包采用 ad-hoc 签名，未经 Apple 公证。若被 macOS 拦截，确认下载来源后按系统「隐私与安全性」提示允许打开；不要关闭系统安全保护。
3. 首次启动创建本机管理员。进入「设置」，检查至少一种本机 Runtime。对应 CLI 需要提前安装并完成自身登录或 API 配置；应用不提供模型账号或额度。
4. 确认任务工作根目录有写入权限。建议首次任务使用独立目录，不放入重要项目。

不需要部署 Web 服务器，也没有在线演示账号。源码安装和环境要求见 [CONTRIBUTING](../CONTRIBUTING.md#安装与本机运行)。

## 2. 创建成员

进入「数字员工」，为每位成员填写名称、员工类型、可用的 Runtime 和系统提示词。第一次可以让全部成员使用同一种已授权 Runtime，无需先配置多个模型。

| 名称 | 员工类型 | 可直接使用的系统提示词 |
| --- | --- | --- |
| 项目经理 | 项目经理 | 根据任务目标协调成员，安排撰写与独立审校，汇总文件和未解决问题，交付后提交人类确认。不要虚构执行结果。 |
| 资料分析师 | 普通员工 | 阅读给定材料，区分事实、推断和缺失信息，把可用素材交给编辑；不虚构来源。 |
| 内容编辑 | 普通员工 | 根据给定素材撰写结构清晰的发布说明，交付实际 Markdown 文件。信息不足时保留未知项，不添加未经材料支持的结论。 |
| 独立审校 | 普通员工 | 对照原始素材检查说明文档，指出虚构、遗漏和歧义，交付审校记录；发现问题时向编辑提出具体修改要求。 |

任务必须且只能选择一位可用项目经理。普通员工可先创建一位；增加独立审校会增加模型调用。团队用于复用成员集合，不是第一次使用的必选项；角色、插件、MCP 和自定义工作流也可以以后配置。

## 3. 创建任务

进入「任务中心 → 新建任务」。标题填「把产品素材整理成一篇发布说明」，内容描述粘贴：

```text
请将以下产品素材整理成中文发布说明，并进行独立审校。

原始素材：
- 产品：一款本地 Markdown 笔记工具。
- 功能：全文搜索、双向链接、Markdown 导出。
- 平台：macOS；目前为测试版。
- 价格：尚未确定。

交付：
1. release-note.md：产品简介、已提供的功能、平台和限制。
2. review.md：逐项核对素材，记录问题、修改建议与未验证事项。

要求：只使用给定事实，不虚构定价、用户量、性能或用户评价。
发现缺失信息时明确标注，不必为本例访问外部网站。
请把文件写入任务工作目录，完成后交给我检查。
```

在「任务成员」加入经理、资料分析师、编辑和审校。流程保持「默认协作」。可选验收标准逐行填写「两个文件均可打开」「未确定价格明确标注」「没有虚构数据」。

如果暂时不想调用模型，选择「保存草稿」；准备好后选择「保存并开始」。启动失败时先查任务列表，已创建的任务可能仍保留，避免反复新建。

## 4. 查看协作与交付

启动后在协作记录查看经理与员工的消息。需要人类信息时直接回答澄清。要检查执行细节，可从相应消息进入「本轮控制台」。

在工作目录查看 `release-note.md` 和 `review.md`，对照素材检查内容。文件不存在、未完成审校或包含虚构信息时，把具体问题反馈给经理；不要仅凭模型说“已完成”就确认。

普通任务到待验收后，检查文件并在客户端显式确认完成。模型选择和实际输出会影响耗时、调用次数与结果，本文不承诺固定费用或一次成功。

## 5. 常见卡点

| 遇到的情况 | 下一步 |
| --- | --- |
| 无法启动应用 | 确认是 Apple Silicon、macOS 13+；检查系统安全提示和对应 Release 的安装说明。 |
| 没有可选经理，或提示只能有一位经理 | 检查员工类型与可用状态；任务成员中只保留一位可用项目经理。 |
| Runtime 不可用或授权报错 | 在设置检查该 Runtime，再确认对应 CLI 能在本机独立运行且账号、模型可用。模型认证由该 CLI 管理。 |
| 保存后没有开始执行 | 区分保存草稿与保存并开始，检查任务状态及启动错误；不要为了重试重复创建任务。 |
| 执行中出现错误 | 打开失败员工的控制台，处理实际错误后从原员工重试；保留已有文件与记录。 |
| 没看到预期文件 | 查看工作目录和协作记录，将缺失文件的路径与要求反馈给经理，再检查实际结果。 |

首次体验成功后，再把成员存为团队，增加自定义工作流或定时自动化。定时自动化的确认规则与普通任务不同，配置前阅读[自动化说明](27-automations.md)。

反馈可提交到 [GitHub Issues](https://github.com/dengdai68/AgentForge/issues)：附应用版本、macOS/芯片、Runtime 名称、复现步骤及脱敏错误摘要。不要附 API Key、完整提示词、私有项目内容或未经检查的日志。
