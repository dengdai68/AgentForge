# 数字员工调用：指令与当前输入

任务提示词读取 Task/Run 的冻结成员，不读取来源团队当前配置。删除员工不改变在途任务身份、角色提示词或原生会话；当前目录可见性由读模型处理，详见 [领域模型](03-domain-model.md)。

完整工作流文件引用和经理指令只给当前 Run 的负责经理 ID；成员类型不能让其他员工获得经理调用语义。

私聊输出仍为严格 `{reply}`。独立群聊输出为 `{reply, mentionAgentIds}`，普通答复用空数组，确需其他员工回答时填当前可用成员 ID，正文中的 @ 不自动投递。所有成员消息公开保留，指定接收者只决定唤醒；没有转交/接棒概念。每条含明确 mentionAgentIds 的新消息都向对应员工入队，包括已参与或正在执行的员工；同一员工按 FIFO 串行处理，失败的队首等待人工重试或取消。完成回调按 deliveryId 幂等，rootMessageId 仅保留来源，不用于抑制后续消息。普通答复及致谢应使用空数组结束讨论。员工会话仍各自隔离，任务派工/咨询协议不变。

文件位置说明：Task系统指令说明业务工作目录可记录真实变化；工作流 artifactPaths 是建议位置，不限定docs。没有位置时按职责交付要求组织文件，不自动注入 docs/<节点>/，不改变历史消息或原生会话。

纯组装入口是 server/prompts.mjs，任务与沟通返回 { systemPrompt, prompt }。不再把身份、规则和历史记录混成用户发言。Runtime 连接测试是独立调用。

## 内容归属

| 类型 | 位置 |
| --- | --- |
| 平台真实性、入口边界、员工身份及自定义工作法 | 应用系统指令 |
| 员工绑定角色的共用提示词（roleSnapshots，历史单角色快照保留） | 应用系统指令，随员工身份段；由快照数据带入，组装层不查询配置 |
| 调用模式、咨询/派工/转交与输出协议 | 应用系统指令 |
| 工作目录、仓库、会话目录、当前 Run/Trace 和输出位置 | 应用系统指令的执行环境；每轮更新 |
| 完整工作流、依赖、人员需求与连线正文 | 经理的私有冻结 workflow.md；系统指令只含路径与读取要求 |
| 员工本次职责和交付要求 | 当前输入；该会话首次接手此职责或要求变化时追加，不附全工作流或人员绑定 |
| 用户目标和约束 | 成员首次输入，后续原生会话保留 |
| 可咨询/转交成员目录 | 应用系统指令中的 ID/名称/简介/能力，无全员 systemPrompt 和节点绑定；候选变化时更新 |
| 当前投递 | 每轮当前输入，含 Dispatch ID、尝试次数，明确续接不是重启任务 |
| 关键状态、问题和交付消息 | 当前输入的变更部分；不重发未变化内容，问题清空也明确送达 |
| 新交接、广播、人类指令、咨询及澄清答复 | 按成员游标首次投递，保留来源与回复关系 |
| 历史对话 | 原生 Claude Code/Codex 会话负责，不作为 transcript 重放 |

“系统指令”是应用指令，不替代 Provider 隐藏系统提示，也不构成操作权限或沙箱。

## 任务调用

Task 冻结配置。Run 每员工独立绑定原生会话；节点变化、咨询、澄清后继续和普通重试仍续接同一成员。经理采用自己的自定义工作法。

调用模式为 manager、node、instruction、consultation、inquiry，以及代码保留的 delivery_review。经理按文件读取完整工作流；其他员工只得到本次工作。经理必须明确单人 managerDecision.nextNodeId/nextAgentId、批量 assignments 或 wait，旧 Task.nodeAssignments 不覆盖选择。后续 @ 员工沿用真实业务 Dispatch 职责，不按静态映射猜测。

经理依据真实 Trace/Dispatch 协调，不以“已派工”文字代替投递事实，不增加业务验收或收尾复核。普通文字可交接；协调动作使用可选 JSON。最终由人类确认完成。

协调对象支持整段 JSON、代码围栏 JSON，或说明后唯一且完整的末尾 JSON 对象；解析遵循字符串/转义边界，不用贪婪括号正则。未围栏形式遇到多对象、尾随说明或不含协调字段时保留普通文字，不猜测路由。原始回复仍保存。

## 新消息不是历史重放

任务协作消息统一公开可查；指定接收人表示当前交给谁处理，不代表消息私密。记录时间线的 sourceMessageId 是投递来源关联，不加入模型提示词或改变输入游标；公开记录统一按成员会话增量补齐；接收人只决定本轮待办和唤醒，不限制公开背景可读性。

原生会话不会自动知道别人刚发来的消息。Store 为成员会话保存平台消息输入游标：

1. 选择当前 Run 的全部未读公开外部消息，不以收件人或旧的全局时间水位过滤；本 Dispatch 明确关联的目标按已送达消息 ID 去重。过去未曾送给该员工、现在首次明确转交的消息仍可送达，不因全局时间游标而丢失。
2. 不复制别人的私有 Provider 对话，不重放本员工已生成的回复。
3. 本轮模型产生真实正文、思考或工具内容时确认输入游标与上下文摘要；最终结果成功同样确认。仅生成快照或连接会话不算送达。已确认后即使执行失败也不重投已送达消息。
4. 启动前失败不确认；无法确认接收的中断仍可能重投，不承诺外部操作 exactly-once。保留真实文件和 Trace，续接先检查已完成操作。
5. 会话保存目标、职责及各必要状态的 SHA256 摘要，不保存第二份原生聊天历史；相同内容省略，变化时追加。原生会话确实丢失后清空这些摘要，重新提供目标与当前职责，但不冒充恢复旧聊天记录。

自动执行的来源是已有 Dispatch（经理派工、人类新指令、咨询答复）或其允许的重试；定时巡检不制造新业务任务。确定性/未知 Runtime 错误停止自动重试；明确临时服务故障最多共三次尝试，详见 docs/08。

managerDecision 接受单人 nextNodeId/nextAgentId、批量 assignments 或 wait:true，各形式可带 rationale，不能混用；consultation 是顶层同级字段，不能嵌入其中。混合协议不会因 nextNodeId:null 被误解为提交验收，平台返回真实协调错误请经理修正，不代猜业务意图。

新指令不打断已发出的调用。人类问题须精确 replyToMessageId 回复；存在未回答问题时 Store 阻止领取任何后续执行。咨询通过真实消息返回原员工，不合并双方会话。

## 普通沟通

私聊输出 JSON 只包含必填 `reply`；独立群聊包含必填 `reply` 和 `mentionAgentIds`（普通答复为空数组），同时发送当前成员的 ID、名称、能力与简介。两种 schema 均严格闭合，不声明 handoffToAgentId，未知字段和空正文拒绝。人类消息按 @/广播选择接收人；群聊员工明确的 mentionAgentIds 可创建对应新消息的定向投递，同一成员串行处理，普通回复不自动广播。不采用任务的 managerDecision/consultation 协议，已保存的原生会话继续续接。

每个私聊/群聊中的员工有独立原生会话。系统指令包含员工工作法、绑定角色的共用提示词、沟通入口边界、reply 正文协议及会话目录。当前输入只含尚未接收的目标消息及新可见消息；已接收目标在失败续接时仅保留 ID，不重复正文，不附近期聊天数组。被回复消息仅在该成员未接收过且不是本人输出时补正文。角色文本随投递快照在发送/显式重试时嵌入；角色编辑或换绑不重建会话，后续投递应用新文本，原生历史中旧指令的影响不承诺消除。

附件只含名称、字节、SHA-256 和真实绝对路径，不拼正文/二进制；未发送附件不注入。定向群聊答复携带目标消息与其原问题的来源关系，使用接收员工自己的会话；同轮去重不修改已保存的公开消息。

确认原生会话且模型产生正文、思考或工具内容时确认输入回执；原生成功返回也确认，即使后续输出格式校验失败。仅会话初始化或快照不确认。输入回执与回复成功分离；失败续接已确认目标仅发引用与继续指令，启动前失败仍发送原文。原生会话丢失或连接变化清空该原生会话的消息回执，当前目标重新送达，旧游标不重放全部历史。Runtime连接/工作目录变化或原生会话不存在时如实记录重建，不自动用旧 transcript 冒充原生恢复；过去材料可经真实历史工具按需查询。

## Provider 适配

- Claude Code：Trace 私有文件 agentforge-instructions.md 经 --append-system-prompt-file 追加；--system-prompt-snapshot off 保证续接使用本轮环境和模式，不保留第一轮旧系统快照。要求 CLI 支持当前参数，不维护旧版本替代分支。
- Codex：developer_instructions / 原生 developerInstructions 承载应用指令；exec resume / thread/resume 精确续接，不重放历史。

提示词快照证明平台本轮传入的内容，不等于模型已正确遵循，也不等于原生会话中旧指令被删除。真实续接验收中曾出现模型沿用旧回复前缀、旧禁止工具规则的情况；普通员工编辑仍不自动重建会话。扩展是否实际注册、调用及移除必须另以原生配置和工具服务日志验证，不能仅凭自报工具清单或回复格式宣称通过。
- 定位参数只接收当前 prompt，不再末尾追加固定规则。
- 历史 MCP 工具目录、连接/schema/分页由真实服务定义提供，不复制进应用系统指令；仅保留历史核对原则。
- Skill 由 Runtime 原生发现和按需激活，不再追加插件路径或逐一读取说明。Provider 自动生成的技能目录/工具定义不属于应用快照。

## 控制台和验证

快照保存平台完整脱敏应用系统指令和本轮输入，下方标记已确认原生会话 ID；不包含 Provider 自动生成的技能/工具目录、内部指令或全部历史。原有快照不改写，缺失与截断如实说明。

tests/prompts.test.mjs 覆盖分层、经理独占工作流、输入游标及两种 CLI 参数。AGENTFORGE_PROMPT_E2E_REAL=1 node scripts/test-prompt-e2e.mjs 在隔离客户端验证真实原生记忆、无历史重放、系统指令生效、澄清阻塞、代码开发、独立测试及界面人类确认；夹具不能冒充真实模型。

已单独完成沟通验证时可加 AGENTFORGE_PROMPT_E2E_TASK_ONLY=1，只执行真实任务及界面验收；证据明确标记 communicationSkipped，不宣称本轮同时测试了沟通。经理错误跳过必需澄清直接提交验收时脚本立即失败，不空等超时。

CLI 员工 systemPrompt、任务消息与精确澄清命令继续生效，不新增输入、权限或全量历史输出。

## 长任务提示词精简

员工输入不再附经理的人员选择提示、空仓库配置、当前消息已有的投递 messageIds、空错误字段，成员简介不重复充当工作法。消息保留 ID、发送者、实际接收人、回复关系、类型、问题类型和完整业务正文；存储 Run/会话/Trace ID 与路由审计不作为消息正文上下文重复发送。完整工作流和人员选择提示仍只给经理。

不再自动向每个员工广播最近 24 条 Artifact 的 ID/版本/哈希；相关交付路径由原始交接消息提供，完整不可变产物目录与证据仍可经历史工具按需查询。目标、职责、验收标准、待答问题、开放缺陷及 Decision 变化仍按会话确认摘要增量送达。只精简新的应用调用，旧快照、游标和领域记录不改写。CLI 消息、配置和查询协议不变。

经理每轮必须给出 managerDecision 或 consultation。只有文字“等待验收”不会改变领域状态；缺少协调决定时在原投递附具体反馈，请原经理会话纠正一次，重复拒收则标记失败，经理明确的 null/null 决定才提交验收。经理作用限于协调与依据成员报告汇总，不重复专业核验或修改员工交付。经理全流程调用的当前投递不带约定性首节点 ID，避免误称其仍在最初阶段。

DeepSeek Harness 调用把同一份应用/角色系统文本保存于 Trace 私有指令文件，由原生 Cordis bridge 注册 systemPrompt.section（interpolate=false），不会塞进 session/prompt 用户消息。输出 schema 以独立系统段说明；SDK 无原生 response_format，返回值须由现有入口解析校验，非法 JSON 不猜测修补。每次调用重载最新/冻结上下文，原生会话仍保留历史；不声称抹除了既有指令影响。

DeepSeek Harness 根据原生 system/message 中的完整应用指令匹配保存布尔验证事实，不倾倒系统正文；该事实证明传入，不保证模型逐条遵循。

角色可通过 handoff.recipientAgentId 交接给任意其他参与者，不能指向自己；@ 人类转换为精确澄清。handoff、consultation、managerDecision 互斥。人类重试以动态“继续”输入恢复原投递，不形成 Message；经理空闲巡检复用成员消息回执，只携带未接收的新消息与状态变化，不另附最近 30 条正文。Trace.inputMessageId 是平台生成的不可变本轮输入 ID，输出 Message.startMessageId 关联它，控制台依据该 ID 定位私有脱敏提示词。

问题发现、处理与核验结果写入 summary/consultation.question，并通过 handoff/consultation 交接。提示词不再附加独立开放问题列表；已废弃的清单输出字段由 Store 明确拒绝，不能悄悄生成另一套状态。

沟通应用提示词保留沟通与 Task/Run 的入口区分、讨论答疑边界和实际交付指引；移除固定中文、逐项 Git/发布/凭据限制、代表自己/经理无特权以及附件读取/非指令的重复句子。输出协议、真实附件路径与统一来源/如实表达规则保持；不改变 API 权限或存量原生历史。

任务系统规则建议 clone 独立成一次工具调用，后续再修改和提交，为内置仓库登记 Hook 提供清晰边界。沟通提示词与协调协议不变。

Task.kind=automation 时替换人类验收/澄清指令：只列经理/员工，只允许 agent consultation，缺少事实由经理协调，不能继续时 automationFailure 明确错误中断。经理以 null nextNodeId/nextAgentId 提交交付，下一触发自动确认；普通任务提示词保持原有规则。Store 和 Orchestrator 同时阻止人类路由，不能只靠提示词。

## 同任务员工并行

同一 Run 内不同员工可并行，同一员工（含经理）的 claimed 投递/原生会话串行。经理可返回 managerDecision.assignments 数组，每项包含 nextNodeId、nextAgentId、instruction；一次派工须全部验证通过才记录定向协作消息和队列，拒绝重复员工、自指派和混合决策。单人 nextNodeId/nextAgentId/instruction/rationale 是同一协议的单项简写，归一为 assignments 后由同一 Store 命令校验、生成定向指令与投递。instruction 可省略，此时使用本轮 summary，其次 rationale；显式空值或非文本拒绝，不丢弃指令。验收仅接受 nextNodeId=null、nextAgentId 省略或 null，不允许同时带派工 instruction。等待其他员工结果使用 managerDecision.wait=true，须存在其他未完成工作；不增加人工开关、不由平台判断业务依赖。经理可在其他员工执行期间处理已返回结果、追加派工，只有没有其他业务投递/执行时才能请求验收。

队列只阻塞同一员工，不让忙碌成员阻塞其他人；经理及员工在执行期间收到的新消息排队，完成后及时唤醒。失败立即标记整项任务并停止领取新投递，已领取的其他员工允许收尾并保存结果/排队交接；人类待所有在途调用收尾后重试原失败投递，多处失败逐一恢复，未解除前不启动其他排队工作。暂停/终止覆盖全部成员进程；重启回收全部在途调用，失败 Run 保持失败且不自动重试。人类澄清停止新投递，在途调用同样收尾。共享目录和任务累计 CHANGE 保持不变，不自动隔离或合并 Git，不以文件快照推断并行员工的独占修改归属。App/CLI 使用同一执行与查询协议，无并行开关或新增配置字段。

任务当前输入的 Message 投影包含 attachments（文件名、字节、摘要及调用前验证的绝对 path），普通指令与澄清回答一致；不把图片或文件正文复制进系统提示词。巡检与普通投递使用同一消息选择与附件校验路径，不再另取最近消息列表。

协调协议拒收与业务执行失败分开处理：拒收事务不产生任何派工、等待问题或验收状态，原始角色报告、文件事实和失败 Trace 保留。Store 把具体原因及原 Trace ID 保存在原 Dispatch 的 routingError，立即在同一成员会话中安排一次格式纠正；纠正仍失败则停止该投递并标记整项任务 failed，巡检不再空转。人工重试继续原投递并重新给予一次纠正机会。反馈只进入本轮输入和控制台审计，不生成系统协作消息，不把模型回复文件当作投递成功回执；外部 Provider 失败仍只由人类显式重试。

合法验收遇到仍在执行、排队或等待答复的工作时，记录延后决定并在其他工作结束后请经理重新协调；延后投递不阻塞后续员工报告，也不消耗协议纠正次数。原始 nextNodeId=null、nextAgentId 非空或同时携带 instruction 属混合决定，明确拒绝，不静默验收。


## 冻结工作流文件

经理的完整工作流不再内联为系统提示词JSON。Orchestrator在调用前由Run Files从Task.workflowSnapshot生成本Trace私有 `workflow.md`（0600、排他创建、最多1MiB），同时物化 Run 级内容寻址的 `workflow/<SHA256>/workflow.md` 稳定入口，系统指令只提供稳定入口绝对路径、SHA256及首次协调/上下文压缩/信息不足时读取要求；生成失败停止该次调用并保留真实错误，不回退注入整份JSON。client/workflow-description.mjs确定性组织总体说明、节点完整正文/人员与交付要求、连线与交接正文，不输出布局数据。编辑预览复用同一投影；文件只能取任务冻结快照，不能从当前模板补查。每次Trace保留自己的文件和原提示词快照，重试创建新Trace，不覆盖旧文件或历史输入。员工的当前节点description并入职责增量，不接收全图。文件被工具读取后仍占上下文，不承诺免Token或强制模型一定完成读取；真实模型验收用仅存在于连线文件中的随机标记核对其实际派工与交付。

冻结 workflow.md 明确标注流程/条件节点，完整保留每条出线的自然语言 condition 与交接正文。条件节点要求根据证据选择一条满足条件的出线，未知先澄清；流程节点不因此失去并行能力。当前节点为 condition 时员工收到判断与理由要求，回报经理选择后续分支，不由平台求值。

同一轮包含 `summary` 与 `consultation` 时，先将非空且与问题正文不同的报告保存为普通角色 Message，再保存问题和等待关系；两条消息关联同一 Trace/本轮输入。缺少报告或正文与问题相同不另造消息，协调失败仍回滚路由并保留原报告；不从控制台补造旧 Message。

新增 Runtime 系统指令传输见 docs/29：Gemini使用私有系统文件与成员独立的原生配置目录，Qwen追加原生系统指令，Kimi Code 2 创建时绑定 Markdown Agent，每轮读取私有指令文件，Pi追加系统文件，OpenCode私有Agent配置。Cursor在私有原生配置与会话目录下执行，应用指令明确保留本机真实用户目录语义；无独立系统指令参数时使用显式应用指令消息前缀，不伪称其为原生system角色。

新六种原生 CLI 的快照在适配器完成用户目录上下文和输出格式合成后保存，逻辑输入只记录一次。未确认原生会话的失败轮次即便产生部分输出，也保留完整派工供新会话恢复；已确认会话的实际进展仍保留消费回执。

六种新增 Runtime 的 Skill 元信息/正文由各自原生加载器管理，不拼入应用系统提示词；平台历史工具共用 withHistoryTools。Kimi 自定义主 Agent 保留原生 base_prompt 以提供真实环境与 Skill 目录，每轮仍读取私有应用说明。

新增 Runtime 的独立子代理正文来自冻结插件并保存在 Trace 私有 agent-prompts 文件，不并入父 Agent 的系统说明；原生目录提供命名空间别名与描述，父 Agent 按原生接口调用并等待。Pi 独立进程只读该正文，继承当前模型、显式基础工具清单与取消，不加载父 Skill/MCP 或其他全局扩展；不创建平台 Task/Run。

沟通执行环境只标明共享工作目录（实际 cwd）；附件绝对路径位于该 cwd 的 attachments，平台正文/历史/校验记录存工作根 records，不向模型提供第二处会话资料目录。群聊成员共享业务文件，提示避免覆盖同一文件；系统不重放其他成员的原生上下文，persona/游标/会话隔离规则不变。Task 的普通/自动化启动目录统一为工作根下 tasks/TaskID/RunID。

## 输入去重与大正文资料

任务和沟通共用纯组装的资料计划：单段目标/职责/验收标准/Decision 或消息正文超过 4096 个 JavaScript 字符时不内联；批量未读协作投影超过8192字符时整包另存资料文件，正文与记录均不截断。消息使用 contentRef（绝对 path、SHA256、字符数），其他段提供资料文件引用。原文由 Run Files 在调用前写入 records/runs/<RunID>/input-materials 或 records/communications/<会话ID>/input-materials，文件名按原文 SHA256 寻址，目录0700、文件0600，排他创建；存在文件须逐字校验，拒绝符号链接及篡改。写入失败停止调用，不静默截断或回退内联。正文、来源、附件与原始消息仍完整保存，文件不是新的业务指令。系统指令要求处理前读取相关资料；已读未变内容无需重读。文件被读后仍消耗上下文，不承诺零 Token。

目标、职责和消息的回执/摘要针对原文，不能针对每轮文件路径计算。经理执行记录和待办按真实 ID 保存每项摘要，只发送 updated 和 removedIds；最近执行窗口移出的记录标 outsideWindowIds，不解释为已完成。待处理问题列表只提供 ID/参与者/类型，问题正文通过消息游标投递一次。每轮经理保留正在执行、排队、等待、失败的数量概览；当前经理 Trace 不充当新的业务进展反复发送。

系统核心规则继续由每个 Runtime 的现有指令通道应用，用户配置的员工/角色工作法不改写。平台经理协议缩减为一个派工示例加字段说明，本人成员目录省略已在身份段出现的简介和能力。Cursor 的应用指令前缀和 Kimi 原生指令文件策略本轮不变，不声称所有 Runtime 都能只在首轮传系统指令。App/CLI 管理、创建、查询、消息与输出业务协议未变化。

## 共享协作背景与当前待办

同一 Run 的公开角色消息在每位当前参与者下一次合法调用时增量送达，包含发给其他成员的派工、报告及人类指令；自己的输出由原生会话保留，不复制回输入。未读背景本身不创建投递、不唤醒全员，也不改变咨询等待与人类验收边界。每轮显式提供本轮处理消息 ID，作为背景已读过的消息后来成为待办时仍按该引用处理，不因正文已读而丢失工作。逐消息接收回执是已读依据，旧水位之前从未送达的公开背景也在下一次合法调用补齐，不改写既有会话或历史。消息游标在选择输入的同一同步阶段取水位，附件异步校验期间新到的消息留待下一轮，不越过未读缺口。上下文压缩或不确定时通过原生历史工具补查，不能承诺模型永远完整记住全部历史。

同批员工报告抵达经理时，只合并其队尾尚未领取、未尝试的报告通知，messageIds 与 coalescedSourceMessageIds 保留全部明确来源；原有 dedupeKey 与新增合并键同样幂等。已领取的调用、人工新指令、咨询、失败重试、巡检、验收延后均不合并，不跨越人类消息的 FIFO 顺序。合并不是业务完成，仍由这一投递成功协调后结算；App/CLI 的协作记录把每条来源关联到同一个真实投递/Trace。

summary 表示完整公开沟通正文，不是另写工作汇报或压缩摘要。有协调动作时只输出一份 JSON，把完整正文放 summary；普通文字仍是合法交接。若原生回复采用“正文 + 唯一尾部协调 JSON”，前文为公开正文，JSON 中的短 summary 不覆盖它；原始 rawResponse 保留，不回填或改写历史消息。员工可按需要向其他成员提问或交接，由接收人决定后续动作；平台不强制交流轮数或新增业务复核。
