# 客户端 Renderer

`app.js` 的任务创建和团队编辑复用 `createEmployeeMultiSelect`：团队展开为员工标签，任务只允许一位经理，团队本身可空且不要求经理。任务列表/详情移除团队标识，员工 Tab 通过共享投影隐藏已删除员工；历史 Trace 入口仍能打开其控制台。

`communication.js` 管理独立群聊创建/重命名/成员编辑，右侧姓名打开员工详情，图标展开最右控制台。详情从认证会话详情按需读取，不进入会话列表摘要；窄屏可关闭面板且保留草稿，成员移除时关闭其当前控制台。契约见 [长期沟通](../docs/17-communication.md)。

MCP 卡片不显示内部安装 ID 或其八位截断值；内部关联、详情操作及 CLI ID 保留。插件卡片仅在有真实版本号时显示版本。员工系统提示词与角色共用系统提示词的创建/编辑输入框默认显示八行，仍可手工调整高度。

协作读模型以消息/事件为主线，按 sourceMessageId 或唯一的已有定向消息、Dispatch/Trace 引用关联真实派工；不按正文、名字或时间猜测，不回填历史。deliveries 明示投递当前状态，history 保留每次执行与重试的实际时间，经理协调为全流程范围。CLI 保留完整投递/执行事实、验收关联及有界文件 ID/名称引用（files 最多8项、fileCount 为总数）；完整文件列表用 artifacts 查询。已知员工交接结果信封从 rawResponse 提取已记录的报告正文，去除重复结构化结果，原始消息和控制台事实不变。客户端协作区展示成员总结、沟通和关键人类状态，保留单一“本轮控制台”入口；不自动附加投递状态、技术失败/重试通知、验收文件清单或平台验收说明。长消息全文一次渲染 Markdown，超过10行仅收起区域，展开不重建 DOM，Run 内保留阅读状态。控制台无顶部错误摘要，失败记录在日志内标红；员工状态按自己的最新 Trace 显示错误/执行中/正常，重试成功后清除旧错误。未验证事项保留员工原文，不自动判定交付质量；存储、调度、模型输入和人类确认规则不变。

任务协作时间线合并同一 Run 的全部 Message、实际 Dispatch 与协调事件。接收人表示处理对象，不表示私密级别：经理派工指向接手员工，工作交接指向经理，咨询/答复保留双方，没有处理对象的发言只显示发送者。sourceMessageId 仅关联同 Run 来源消息，正文与首个实际投递合并；同源额外投递归入同一消息；无法用已存引用关联的投递独立注明，不猜测历史来源。节点、尝试次数、重试/错误和真实投递状态保留在读模型及控制台；协作消息只提供单一控制台入口。任务确认、取消、暂停、恢复等事件按时间保留，不输出原始 Provider 帧或提示词。

本目录仅为客户端 renderer，已移除独立 Web 登录初始化、下载入口及展示分支。服务始终提供客户端样式，CLI 设置不再按浏览器模式隐藏。

本目录随客户端打包，不提供独立 Web 产品。

工作目录与CHANGE不再使用docs/repos白名单：当前文件按目录展开、每页200项继续加载，缓存属于Run，刷新重读展开项、错误原位重试。CHANGE按完整相对路径合并目录，含根文件和已删除项，不依赖当前文件页加载。大文件可列出和下载，预览/文本差异超限明确提示；不把当前文件当作历史快照。工作流编辑使用“建议交付位置”，不强制docs。

「设置 → 更新 → 插件更新」复用全局 tokens，提供开关、整数分钟周期（1–1440，默认2）、保存与立即检查；插件市场不显示更新控制。仅设置页可见时轮询状态，离开清除轮询；服务端负责真正调度。未保存草稿不会被刷新覆盖；关闭时仍可立即检查。部分来源失败与成功更新同时如实展示，错误细节在本机日志。

沟通没有已选会话时，列表成功加载后打开 updatedAt 最新会话；错误与空列表不猜测。任务首次打开控制台且无已选成员时，按 Trace.startedAt（缺少则 createdAt）选最近执行的有效成员，不以长任务结束时间抢占。两处显式选择均在刷新中保留，显示选择不改变派工、会话或 CLI 契约。

团队空态不展示创建数字员工入口，只提示右上角创建团队。MCP 详情的编辑入口复用安装表单，填充脱敏 JSON；无效输入就地报错并保留草稿，取消不写入，成功刷新列表。保存生成新版本并更新当前员工，历史任务不变；不新增样式系统。

任务中心只在顶栏显示当前页面名称（任务中心/归档历史）；搜索行上方的重复标题保留为无占位的屏幕阅读器语义。搜索、重置、归档和创建逻辑不变，客户端共用。

协作记录合并消息、实际派工与协调事件，不在末尾固定附加经理验收结论；新提问自然接在最终经理消息之后。人类确认仍在顶部，并保留确认框中的冻结要求；不再提供停止答疑入口，未归档任务可以继续消息，归档只读。人类气泡无强制最小宽度，内边距 10px/12px、首尾段落不留额外空白；不更改 HTTP/CLI 或任务状态机。

任务与沟通控制台过滤无正文的常规执行通知，仅展示正文/思考/工具/提示词及有意义的异常与恢复；不以文本关键词过滤业务正文。过滤在共享纯投影中完成，原始审计、日志、CLI/API 和历史分页边界保持原样。

控制台完整显示已脱敏系统指令与本轮输入，下方显示该 Trace 的 Claude Code/Codex/DeepSeek Harness 会话 ID，未确认则标明未记录。任务和沟通共用 renderer/hydrator，不展示工具审计详情和重复快照说明；同一工具调用内重复的相同公开输入只显示一次，不合并不同调用。

团队和工作流支持名称/说明搜索，过滤后再分页，查询变化回第一页，刷新不销毁输入框。任务搜索后的归档/新建操作同排，任务名字段收窄；各目录操作区上移为紧凑 44px，保留标题语义。侧栏直接复用当前应用图标 PNG，不再用另一套 CSS 标志。CLI 配置/输出不变。

沟通控制台顶部仅最新/刷新；唯一成员不重复显示姓名，群聊成员切换和更早记录在工具栏外保留。该精简不改变成员查询、分页、Runtime 或 CLI。

沟通 composer 先上传附件再发送当前会话 attachmentIds，失败保留草稿和已上传引用。最右侧控制台由 app.js 注入已有 renderChatStream/hydration，不复制工具格式化；可从聊天标题栏或成员姓名后的图标打开，控制台提供员工名称与关闭按钮。仅展开时按成员/游标轮询，pending 不再显示未读点，开关不重建输入框。市场头像复用员工 palette。

CLI 安装作为独立设置分类，始终由客户端展示；宿主方法缺失时明确报告客户端接口错误，不切换到浏览器产品模式。默认任务工作目录为 ~/agentforge；保存的目录和既有任务路径不变，配置/鉴权目录仍独立。

员工插件/MCP 选择器在鼠标移出整体选择区、点击表单其他区域或焦点离开搜索/候选区时收起；候选列表及输入到列表的间隙仍可穿越。重复点击已聚焦输入会重新打开；Escape 收起且不关闭编辑框，隐藏候选时将其内部焦点还给输入。事件随表单销毁，不注册逐弹窗累积的 document 监听；不改变扩展选择/API/CLI 协议。

插件详情使用一个有界正文滚动区，标题/删除/关闭固定，Skill/Subagent/Hook 标签吸顶；概览可随正文滚动，确保长简介、上百 Skill 和窄窗口都能读到最后一项。员工/插件/MCP 卡片固定名称与三行简介空间，Runtime/操作对齐，完整内容仍在详情/编辑中读取，不修改原字段。

员工、角色、插件和 MCP 的 `directory-toolbar` 将搜索与创建/手动安装放在同一行；过滤后分页、清空恢复列表，保留无可见标签的可访问搜索名称。市场复用员工卡片样式。插件/MCP 详情的删除使用应用内确认；引用错误就地显示，成功刷新目录，不修改员工选择或冻结历史。

「角色」是 BUILD 组独立目录：名称＋纯文本提示词的创建/编辑/删除复用员工卡片与删除确认弹框，删除被绑定角色时就地展示引用员工错误；卡片含头像列、显示绑定员工数与角色 ID，标题保持完整宽度。员工编辑弹框提供角色搜索、逐个添加与移除；角色、插件、MCP 共用框内标签多选选择器，不显示优先级编号或排序操作，同名选项以 ID 区分；提交有序 roleIds 数组（[] 为不绑定），卡片显示整组角色名。

角色入口登记在统一 NAVIGATION 中，外观 → 侧栏展示支持隐藏、重载保留与恢复默认，空 BUILD 分组随入口一起隐藏。入口采用继承当前颜色的 SVG 人物名牌图标，Electron 的 compact.css 提供同形 SVG 蒙版，避免缺失蒙版显示成黑方块；不改变角色命令或 CLI 协议。

市场空态、无搜索结果、读取中和失败状态在卡片网格外独立整行展示。协作和沟通仅人类发送的消息靠右，员工（含发给人类）仍靠左，正文保持可读的左对齐；方向只在 renderer 判断，不改变共享投影或 CLI 输出。

设置保存绝对工作目录时，服务自动创建缺失目录；失败就地提示并保留输入，不改变之前保存的根。旧任务不迁移，应用配置/鉴权目录不受影响。

插件详情/员工搜索器展示各 Runtime 兼容性；详情注明静态兼容边界及具体不兼容原因，组件标记适用 Runtime。员工切换 Runtime 不静默丢弃选择，不兼容项禁选、已选项提示并阻止保存；最终校验仍在服务端。安装同时支持市场 Git 远程条目，任一失败不发布部分安装。

- `settings.mjs`：常规、外观、Runtime、仓库、CLI 与日志设置。
- `communication.js`：长期私聊/群聊和 Markdown。

所有数据来自认证 HTTP/SSE。控制台点击员工后每页读取 50 条，可见工具行无需展开就读取 Bash 命令和 Read/Write 文件摘要（复用完整性校验内容缓存）；工具正文和提示词在展开且接近视口时读取。成功 Read 显示 Done，失败保留输出，Write 直接显示已记录写入文本，不能解析时回退原始内容；协作记录先渲染 30 条。工作目录、CHANGE 和文件预览按选择加载。

团队编辑通过姓名/能力搜索候选（最多 20 个），已选员工在同一个输入框内显示；工作流长弹窗受视口约束、节点编辑可折叠。展示状态按 Run 保留，不写入领域对象。

当前文件和 CHANGE 共用 `workingFileTree`，保持相同声明根、图标与排序，各自保留阅读状态；交付版本页面及加载逻辑已移除，不删除后台 Artifact。协作 `message.sent` 正文只在协作记录展示，不在控制台重复；标题左侧返回按钮保留列表搜索。

两种文件树共用根目录紧凑样式，不给折叠分组预留空白。当前文件刷新旁的下载按钮保存选中文件的完整当前字节，使用认证 attachment 接口；未选择禁用，失败就地提示，保留原文件名。

Markdown 使用本地 marked/DOMPurify；Shell 与代码保留原文。主题只影响展示。工作目录图标来自 [vscode-icons](icons/vscode/README.md)，保留原许可。

提示词按 Trace 开始时间参与时间线排序，分页未加载到其时间时不提前展示；交错记录也只显示一次。运行中员工、协作类型/状态和沟通发送者使用共享语义色，不改变领域状态。

首次安装从 GitHub Release 下载；应用更新由“设置 → 更新 → 应用更新”提供。应用图标保留用户原始 PNG，按侧栏、Dock/安装包和菜单栏用途生成展示资源。
